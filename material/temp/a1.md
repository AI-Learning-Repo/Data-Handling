### 4. Data Cleaning

#### 4.1 Missing Age Imputation
```python
median_age = df_titanic["age"].median()
df_titanic["age"] = df_titanic["age"].fillna(median_age)
```
- **Explanation:** Computes the sample median ($28.0$) across available rows and replaces `NaN`s in-place. The median is chosen over the mean ($29.7$) because it is resistant to skewness and extreme values.

#### 4.2 Dropping `deck`
```python
df_titanic = df_titanic.drop(columns=["deck"])
```
- **Explanation:** Over $77\%$ of records lack `deck` data. Imputing over three-quarters of a column would inject synthetic variance and bias.

#### 4.3 Verifying Cleaning
```python
print("Missing age values:", df_titanic["age"].isnull().sum())
print("Is 'deck' in DataFrame:", "deck" in df_titanic.columns)
```
- Confirms `age` missing count is $0$ and the `deck` column has been removed.

### 6. Feature Engineering & Categorical Encoding

```python
# Create combined family size metric
df_titanic["family_size"] = df_titanic["sibsp"] + df_titanic["parch"]

# One-hot encode nominal 'sex' variable
df_titanic_encoded = pd.get_dummies(df_titanic, columns=["sex"], drop_first=True)

display(df_titanic_encoded[["sibsp", "parch", "family_size", "sex_male"]].head())
```
- **Explanation:**
  - `family_size`: Combines horizontal (`sibsp`) and vertical (`parch`) family ties into a single aggregate metric representing total traveling companions.
  - `pd.get_dummies(..., drop_first=True)`: Converts $K$ categories into $K-1$ binary ($0/1$) dummy columns. Dropping the first level (`female`) avoids the *dummy variable trap* (perfect multicollinearity) while preventing artificial ordinal relationships ($1 < 2$).

## 15. Knowledge Check: Complete Answer Key

1. **Why not clean before EDA?**
   Cleaning without EDA risks applying incorrect assumptions (such as deleting valid extreme fares or imputing non-random missingness blindly). EDA diagnoses the specific issues that guide appropriate cleaning decisions.
2. **Difference between Univariate, Bivariate, and Multivariate Analysis:**
   - *Univariate:* Investigates the distribution, spread, and central tendency of a single variable (e.g., histogram of `age`).
   - *Bivariate:* Investigates the relationship between two variables (e.g., survival rate across `sex`).
   - *Multivariate:* Examines interactions among three or more variables simultaneously (e.g., survival across `class` and `sex` via `hue`, correlation heatmaps, pairplots).
3. **Why median over mean for skewed distributions?**
   The sample mean minimizes squared errors and is pulled toward extreme tails. The median minimizes absolute errors and represents the 50th percentile, making it robust against extreme values.
4. **Should high fares automatically be deleted?**
   No. Outliers must be evaluated via domain context. The high Titanic fares represent valid first-class suites. Deleting them removes real information and distorts the socioeconomic structure of the data.
5. **Why repeat EDA after cleaning?**
   Cleaning modifies the underlying distribution (e.g., median imputation creates a spike at the median and reduces variance). Post-cleaning EDA verifies that modifications succeeded and checks for unintended side effects.
6. **What does a correlation of $+1.0$ indicate?**
   A perfect positive linear relationship: as feature $X$ increases, feature $Y$ increases in exact constant linear proportion.
7. **Why correlation does not imply causation:**
   Correlation quantifies mathematical co-movement. It cannot rule out confounding variables, reverse causality, selection bias, or coincidental associations.
8. **Why drop `deck`?**
   With $77.2\%$ missing values, any imputation would inject synthetic noise or bias, as the remaining sample is too small to reliably infer the missing values.
9. **What is imputation?**
   The statistical process of replacing missing (`NaN`, `null`) data points with substituted estimates (e.g., mean, median, mode, or k-Nearest Neighbors estimates).
10. **Why verify data types during inspection?**
    Data types control programmatic behavior. Numerical values stored as strings (`"50"`) fail mathematical operations, and categorical variables stored as numeric values can mislead algorithms into assuming mathematical ordering.
11. **What is feature engineering?**
    The process of using domain knowledge and data transformations to create new input variables (e.g., `family_size = sibsp + parch`) that make underlying patterns more accessible to machine learning models.
12. **Why not encode nominal variables as `male = 1, female = 2`?**
    This creates *false ordinality*. Algorithms with arithmetic components (linear regression, neural networks, distance metrics) would incorrectly assume $\text{female} > \text{male}$ and that $\text{female}$ is twice the value of $\text{male}$.
13. **Why use `!` in Google Colab?**
    The exclamation mark escapes the Python runtime kernel and passes the command directly to the host operating system's shell environment.
14. **What are `%` and `%%` magic commands?**
    - `%` (Line magic): Operates on a single line of code (e.g., `%time statement`).
    - `%%` (Cell magic): Operates on the entire contents of the cell (e.g., `%%writefile filename.py`, `%%time`).
15. **Why use `hue` in Seaborn?**
    `hue` maps a categorical variable to color properties, adding a third dimension to 2D plots and enabling visual subgroup comparisons and interaction analysis.

## 16. Final Reflection: Detailed Answers

- **Q1: Why is it dangerous to assume every dataset needs the same cleaning procedure?**
  Applying a rigid checklist leads to errors: complete datasets (e.g., Iris) can be over-processed, while non-normal distributions (e.g., Titanic fare) can be distorted by inappropriate techniques (such as mean imputation or standard Z-score filtering). Cleaning must be tailored to the specific characteristics of each dataset.
- **Q2: Why is an outlier not automatically an error?**
  Extreme values frequently reflect genuine real-world phenomena (e.g., high wealth, rare sensor events, peak loads). Treating valid outliers as errors removes valuable signal about high-impact cases.
- **Q3: Why perform EDA both before and after cleaning?**
  Pre-cleaning EDA identifies problems (missing values, skewness, outliers) and guides cleaning decisions. Post-cleaning EDA confirms that the data changes succeeded and checks for unintended side effects (such as distorted distributions or altered correlations).
- **Q4: What is the difference between finding an EDA relationship and building a predictive model?**
  EDA relationships are descriptive and show correlations within the observed dataset. A predictive model is an inductive mapping function designed to generalize to unseen data, requiring strict separation of training/testing sets, cross-validation, and guards against data leakage.
- **Q5: What did the Titanic dataset reveal that was not obvious from column names alone?**
  Column names do not reveal the large survival advantage for females over males, the sharp drop in survival for 3rd-class passengers, the $77\%$ missingness in `deck`, or the shared ticket pricing structure where single tickets covered multi-passenger suites.
