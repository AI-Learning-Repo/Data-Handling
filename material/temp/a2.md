### 4. Data Cleaning

#### 4.1 Handling Missing Values
```python
# 1. Impute missing payment methods with mode ('credit card')
mode_payment = df_taxis["payment"].mode()[0]
df_taxis["payment"] = df_taxis["payment"].fillna(mode_payment)

# 2. Drop rows with missing borough identifiers (< 0.5% of data)
df_taxis.dropna(subset=["pickup_borough", "dropoff_borough"], inplace=True)

# 3. Verification
print("Missing values after cleaning:")
display(df_taxis[["payment", "pickup_borough", "dropoff_borough"]].isnull().sum())
```
- **Explanation:** Mode imputation is appropriate for `payment` because the feature is nominal and heavily dominated by `credit card` ($71.6\%$). Missing boroughs ($<0.5\%$ of total rows) are dropped because neighborhood location cannot be reliably imputed from summary statistics.

---

#### 4.2 Handling Zero-Distance Anomalies
```python
# Filter out zero-distance trips
zero_dist_count = (df_taxis["distance"] == 0).sum()
print(f"Number of zero-distance trips: {zero_dist_count}")

# Retain only physically valid trips (distance > 0)
df_taxis = df_taxis[df_taxis["distance"] > 0].copy()
```
- **Explanation:** A trip with zero distance but a positive fare reflects a canceled ride or a faulty meter start. Removing these records cleans the physical relationship between distance and fare and avoids division-by-zero errors when calculating `tip_pct`.

### 6. Feature Engineering & Preprocessing

#### 6.1 Creating Tip Percentage and Trip Duration
```python
# 1. Tip percentage relative to base fare
df_taxis["tip_pct"] = (df_taxis["tip"] / df_taxis["fare"]) * 100

# 2. Trip duration in minutes using vectorized datetime arithmetic
df_taxis["pickup"] = pd.to_datetime(df_taxis["pickup"])
df_taxis["dropoff"] = pd.to_datetime(df_taxis["dropoff"])
df_taxis["duration_min"] = (
    df_taxis["dropoff"] - df_taxis["pickup"]
).dt.total_seconds() / 60.0

display(
    df_taxis[["distance", "fare", "tip", "tip_pct", "duration_min"]].head()
)
```
- **Explanation:**
  - `tip_pct`: Normalizes tip behavior across different trip lengths.
  - `.dt.total_seconds() / 60.0`: Converts Pandas `Timedelta` objects into a clean continuous numerical float representing elapsed minutes.

#### 6.2 One-Hot Encoding
```python
df_taxis_encoded = pd.get_dummies(
    df_taxis,
    columns=["color", "payment", "pickup_borough"],
    drop_first=True,
    dtype=int,
)

display(df_taxis_encoded.head())
```
- **Explanation:**
  - `drop_first=True`: Drops the reference category for each feature (`color_yellow`, `payment_credit card`, `pickup_borough_Bronx`) to prevent perfect multicollinearity (the **dummy variable trap**).
  - `dtype=int`: Encodes indicators as `0` and `1` instead of `True` and `False`.
  - **False Ordinality:** Avoids assigning arbitrary numerical orders (e.g., `Manhattan=1, Queens=2, Brooklyn=3`), which would mislead algorithms into interpreting mathematical hierarchies ($3 > 2 > 1$).

## 12. Knowledge Check: Answer Key

1. **Why didn't we delete all taxi fares greater than $100?**
   Fares $> \$100$ reflect valid trips to distant destinations or out-of-city airports. Outliers should only be removed when there is evidence of physical impossibility or data-entry error.
2. **Why use `drop_first=True` in `pd.get_dummies`?**
   To avoid the **Dummy Variable Trap** (perfect multicollinearity). For a binary variable like `color` (`yellow`/`green`), knowing `color_yellow == 0` guarantees the taxi is green. Retaining both columns adds redundant information that can cause numerical instability in linear models.
3. **What is false ordinality?**
   Assigning arbitrary numbers to nominal categories (e.g., `Manhattan = 1, Queens = 2, Brooklyn = 3`) that leads models to treat them as an ordered mathematical scale ($3 > 2 > 1$).
4. **Why is EDA considered iterative?**
   Cleaning steps (like mode imputation and outlier filtering) alter the underlying distributions and relationships. EDA must be repeated after cleaning to verify that transformations did not introduce unintended distortions.
5. **What is the GIGO Principle?**
   **Garbage In, Garbage Out**. If an algorithm is trained on incomplete, biased, or noisy data, its predictions will be unreliable regardless of model complexity.

## 13. Final Reflection Questions: Detailed Answers

1. **Why convert `pickup` and `dropoff` to `datetime` before calculating duration?**
   Raw timestamps are stored as text strings (`object`). Strings do not support arithmetic operations. Converting them to `datetime64` enables vectorized time-delta arithmetic (`dropoff - pickup`) to compute exact elapsed durations in minutes.
2. **Why is cash tip recorded as $0.00, and what does this teach us about data collection?**
   Cash tips are handed directly to drivers and are not entered into the taxi meter system, whereas credit card tips are logged automatically. This illustrates that datasets reflect their underlying collection mechanisms and limitations, not necessarily complete real-world truth.
3. **Why should we never apply a single generic cleaning script to all datasets?**
   Different datasets have different characteristics and data-quality issues. The `taxis` dataset requires mode imputation, anomaly filtering, timestamp parsing, and categorical encoding, whereas the `iris` dataset needs none of these steps. Applying a generic cleaning script risks over-processing clean data or applying incorrect assumptions to messy data.
