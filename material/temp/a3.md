# Building Streamlit Applications

This document provides an in-depth, beginner-friendly explanation of the concepts, architecture, and code covered in the Streamlit laboratory guide. The explanations are structured to provide full clarity on how Streamlit operates, what happens behind the scenes during execution, and why specific design patterns are used.

---

## 1. Architectural Foundation & Execution Model

### 1.1 How Streamlit Differs from Traditional Web Frameworks
In traditional web development (such as Flask, Django, or React/Node.js), building an interactive application requires managing three distinct layers:
1. **Frontend:** User interface markup and styling (HTML/CSS).
2. **Client-Side Logic:** Handling browser events, clicks, and state changes (JavaScript).
3. **Backend:** Web servers, routing endpoints (e.g., `/api/data`), and request/response lifecycles (Python).

Streamlit removes this separation. You write standard, procedural Python code that runs sequentially from top to bottom. Streamlit automatically converts your Python variables and function calls into frontend components, manages the bidirectional communication via WebSockets, and handles the application state.

```
+-------------------------------------------------------------------+
|                     Streamlit Execution Cycle                     |
+-------------------------------------------------------------------+
|  1. User interacts with a widget (e.g., moves a slider).          |
|  2. Frontend sends an event payload via WebSocket to the server.  |
|  3. The Python script reruns entirely from Line 1 to the end.     |
|  4. Widgets output their newest values to their assigned variables|
|  5. Output components re-render in the browser to match state.    |
+-------------------------------------------------------------------+
```

### 1.2 The Reactive Execution Cycle
Streamlit relies on a **reactive execution model**:
* **Top-to-Bottom Execution:** Whenever a user changes an input widget (e.g., selecting an item in a dropdown), Streamlit re-executes the **entire** Python script from the first line to the last line.
* **Direct Variable Assignment:** Widgets do not require custom event listeners. The function call that draws the widget also returns its current value directly into a Python variable (e.g., `x = st.slider(...)`).
* **Input Commitment Rules:**
  * *Immediate Triggers:* Sliders, checkboxes, radio buttons, selectboxes, and multiselects trigger an immediate rerun as soon as their value is altered.
  * *Buffered Triggers:* Text inputs (`st.text_input`, `st.text_area`) require the user to press **Enter** or click outside the text box before committing the value and triggering a script rerun.

### 1.3 The Google Colab Port Proxy Architecture
Google Colab instances run inside virtualized Linux containers located on remote Google Cloud servers. They do not have direct public IP addresses accessible from your local browser.

```
+--------------------------------------------------------------------+
| Google Colab Linux Container                                       |
|                                                                    |
|   +----------------------------+                                   |
|   | Streamlit Server (Port 8501)|                                  |
|   +--------------+-------------+                                   |
+------------------|-------------------------------------------------+
                   | (Internal Loopback Bridge)
                   v
+--------------------------------------------------------------------+
| Google Cloud Proxy Gateway (*.colab.googleusercontent.com)         |
|                                                                    |
|   ├── Option A: Rendered in Notebook Cell via <iframe>             |
|   └── Option B: Rendered in Full-Screen Browser Tab                |
+--------------------------------------------------------------------+
```

* To expose port `8501` securely without third-party tunneling services (such as Ngrok or Localtunnel, which often require authentication tokens or trigger firewall warnings), Colab provides an internal JavaScript-based proxy API: `google.colab.kernel.proxyPort(8501)`.
* This maps the internal container port to an authenticated external URL under `*.colab.googleusercontent.com`.

## 2. Environment Setup & Server Initialization

### Code Walkthrough

```python
# 1. Install Streamlit and visualization libraries
!pip install -q streamlit plotly seaborn matplotlib

# 2. Write baseline application
with open("app.py", "w") as f:
    f.write("""import streamlit as st
st.set_page_config(page_title="Streamlit Colab Lab", layout="centered")
st.title("Streamlit Environment Online")
st.success("Server initialized successfully. Proceed to Module 1 below.")
""")

# 3. Terminate any previous instances cleanly
import subprocess
import time
subprocess.run(["pkill", "-f", "streamlit"], stderr=subprocess.DEVNULL)

# 4. Launch Streamlit server in the background
subprocess.Popen([
    "streamlit", "run", "app.py",
    "--server.port", "8501",
    "--server.headless", "true",
    "--server.enableCORS", "false",
    "--server.enableXsrfProtection", "false"
], stdout=subprocess.DEVNULL, stderr=subprocess.DEVNULL)

# Allow server time to bind port
time.sleep(3)

# 5. Generate direct URL and display embedded iframe
from google.colab import output
from google.colab.output import eval_js

proxy_url = eval_js("google.colab.kernel.proxyPort(8501)")

print("=====================================================================")
print(f"FULL-SCREEN DIRECT URL: {proxy_url}")
print("=====================================================================")

# Render interactive iframe in notebook cell output:
output.serve_kernel_port_as_iframe(8501, height='650')
```

### Detailed Explanation

1. **Package Installation (`!pip install -q ...`):**
   * The `-q` (quiet) flag suppresses verbose output while installing Streamlit, Plotly, Seaborn, and Matplotlib.
2. **Baseline File Creation (`with open("app.py", "w") as f:`):**
   * Creates an initial `app.py` script so the Streamlit server has a valid target file to host when it boots.
3. **Process Termination (`subprocess.run(["pkill", "-f", "streamlit"]...)`):**
   * If a previous Streamlit server is already running on port 8501, re-launching it will result in a port conflict (`Address already in use`). `pkill -f streamlit` sends a termination signal to any active Streamlit processes.
4. **Asynchronous Background Execution (`subprocess.Popen`):**
   * `subprocess.run` blocks execution until a program finishes. Because a web server runs indefinitely, `subprocess.Popen` is used instead to launch the server as an independent background process.
   * `--server.port 8501`: Sets the network port.
   * `--server.headless true`: Informs Streamlit that it is running on a server without a native display monitor, suppressing local browser launch attempts.
   * `--server.enableCORS false` and `--server.enableXsrfProtection false`: Disables Cross-Origin Resource Sharing (CORS) and Cross-Site Request Forgery (XSRF) restrictions that would otherwise block the iframe embedded inside the Colab domain.
5. **Port Binding Delay (`time.sleep(3)`):**
   * Provides a 3-second buffer for the operating system to allocate resources, load Python modules, and open the network socket before Colab attempts to connect to it.
6. **Proxy URL Generation & IFrame Display:**
   * `eval_js("google.colab.kernel.proxyPort(8501)")` executes JavaScript in the Colab client to resolve the public routing URL for port 8501.
   * `output.serve_kernel_port_as_iframe(8501, height='650')` embeds an HTML `<iframe>` directly into the notebook output cell.

## 3. Module 1: Basic Input Widgets

### Code

```python
%%writefile app.py
import streamlit as st

st.set_page_config(page_title="Module 1: Widgets", layout="centered")
st.title("Module 1: Basic Input Widgets")

st.info("Remember: Press Enter after typing in the text input to commit your change.")

# Text input
name = st.text_input("Enter your name:", placeholder="Type name and press Enter...")
if name:
    st.success(f"Hello, {name}!")

# Numerical input
age = st.number_input("Enter your age:", min_value=0, max_value=120, value=25, step=1)
st.write(f"Registered age: **{age}**")

# Slider
score = st.slider("Select an evaluation score:", min_value=1, max_value=10, value=5)
st.write(f"Selected score: **{score}**")

# Button trigger
if st.button("Execute Action"):
    st.info("Action button triggered.")

# Checkbox toggle
if st.checkbox("Show technical details"):
    st.write("Additional technical metadata displayed conditionally.")

# Categorical options
color = st.radio("Select primary color:", ["Red", "Green", "Blue"])
st.write(f"Selected color: **{color}**")

option = st.selectbox("Select discrete category:", [f"Category {i}" for i in range(1, 6)])
st.write(f"Selected category: **{option}**")

langs = st.multiselect(
    "Select technical proficiencies:", 
    ["Python", "R", "SQL", "C++", "Julia"]
)
st.write(f"Proficiencies: **{', '.join(langs) if langs else 'None selected'}**")
```

### Detailed Explanation

* `%%writefile app.py`: A Jupyter notebook magic command that overwrites the contents of `app.py` with the code in that cell.
* `st.set_page_config(...)`: Sets the browser tab title and page structure (`layout="centered"` constrains content to a readable central column; `layout="wide"` utilizes the full width of the screen). *Note: This must be the very first Streamlit command in the script.*
* `st.text_input`: Renders a text box. It returns an empty string `""` until the user enters text and commits it by pressing **Enter**. When non-empty, the conditional `if name:` evaluates to `True`.
* `st.number_input`: Constrains numerical values using `min_value`, `max_value`, and step increments (`step=1`). It guarantees that the returned variable is numeric (integer or float), avoiding manual string-to-integer conversion.
* `st.slider`: Provides a visual draggable bar over a continuous range.
* `st.button`: **Crucial concept for beginners:** An `st.button` returns `True` **only on the specific rerun cycle triggered by clicking it**. On any subsequent rerun triggered by interacting with another widget (such as moving the slider), the button automatically evaluates back to `False`.
* `st.checkbox`: Returns a persistent boolean (`True` or `False`), useful for conditionally hiding or displaying UI elements.
* `st.radio` vs `st.selectbox`: Both enforce single-choice selection from an iterable list. Radio buttons expose all options simultaneously; selectboxes use a dropdown menu to conserve vertical screen space.
* `st.multiselect`: Allows zero, one, or multiple items to be selected from a list, returning the chosen values as a standard Python `list`.

## 4. Module 2: Tabular Data Displays and Metrics

### Code

```python
%%writefile app.py
import streamlit as st
import pandas as pd
import numpy as np

st.set_page_config(page_title="Module 2: Data Display", layout="wide")
st.title("Module 2: Data Display & Metrics")

np.random.seed(42)
df = pd.DataFrame(
    np.random.randn(8, 4),
    columns=["Metric A", "Metric B", "Metric C", "Metric D"]
)

st.subheader("1. Interactive DataFrame (`st.dataframe`)")
st.caption("Scrollable, sortable, and resizable table representation.")
st.dataframe(df, use_container_width=True)

st.subheader("2. Interactive Data Editor (`st.data_editor`)")
st.caption("Allows direct cell editing. Double-click any cell to modify values.")
edited_df = st.data_editor(df, use_container_width=True)

st.subheader("3. Static HTML Table (`st.table`)")
st.caption("Fixed presentation suitable for small summary matrices.")
st.table(df.head(3))

st.subheader("4. Metric Cards (`st.metric`)")
col1, col2, col3 = st.columns(3)
col1.metric("Server Throughput", "1,240 req/s", "45 req/s")
col2.metric("Response Latency", "42 ms", "-4 ms", delta_color="inverse")
col3.metric("Error Rate", "0.02%", "0.00%")
```

### Detailed Explanation

* `st.dataframe(df, use_container_width=True)`:
  * Renders a dynamic, high-performance table driven by Apache Arrow on the backend.
  * Users can click column headers to sort, resize column widths, and search/filter rows directly in the browser without requiring Python script re-execution.
  * `use_container_width=True` forces the element to stretch across the full available page layout width.
* `st.data_editor(df)`:
  * Renders an editable spreadsheet interface.
  * When a user double-clicks a cell and modifies its value, Streamlit reruns the script and assigns the updated data to the variable `edited_df` as a new pandas DataFrame.
* `st.table(df)`:
  * Generates a static, standard HTML table. It disables scrolling, sorting, and user interaction. It is suitable only for small summary tables (e.g., `.describe()` or confusion matrices).
* `st.metric(label, value, delta, delta_color)`:
  * Displays a Key Performance Indicator (KPI) card.
  * `delta`: Displays a change indicator below the primary value with an arrow (e.g., `+45 req/s`).
  * `delta_color="normal"` (default): Positive changes are green; negative changes are red.
  * `delta_color="inverse"`: Inverts the color logic (negative changes turn green; positive changes turn red). This is used for metrics where a lower number indicates better performance, such as server latency or error rates.

## 5. Module 3: Visualization Frameworks

### Code

```python
%%writefile app.py
import streamlit as st
import pandas as pd
import numpy as np
import matplotlib.pyplot as plt
import seaborn as sns
import plotly.express as px

st.set_page_config(page_title="Module 3: Visualizations", layout="wide")
st.title("Module 3: Visualization Frameworks")

np.random.seed(42)
data = pd.DataFrame({
    "Step": np.arange(100),
    "Series_1": np.random.randn(100).cumsum(),
    "Series_2": np.random.randn(100).cumsum(),
    "Category": np.random.choice(["Type A", "Type B", "Type C"], 100)
})

col1, col2 = st.columns(2)

with col1:
    st.subheader("Matplotlib (Static)")
    fig, ax = plt.subplots(figsize=(6, 4))
    ax.plot(data["Step"], data["Series_1"], color="steelblue", label="Series 1")
    ax.set_xlabel("Time Step")
    ax.set_ylabel("Value")
    ax.legend()
    st.pyplot(fig)

with col2:
    st.subheader("Seaborn (Statistical)")
    fig, ax = plt.subplots(figsize=(6, 4))
    sns.scatterplot(data=data, x="Series_1", y="Series_2", hue="Category", ax=ax)
    st.pyplot(fig)

st.divider()

st.subheader("Plotly (Interactive Client-Side)")
fig_px = px.scatter(
    data, 
    x="Series_1", 
    y="Series_2", 
    color="Category", 
    title="Interactive Scatter Plot (Supports Zoom, Pan, and Hover Tooltips)"
)
st.plotly_chart(fig_px, use_container_width=True)

st.divider()

st.subheader("Native Streamlit Charts")
st.line_chart(data[["Series_1", "Series_2"]], use_container_width=True)
st.bar_chart(data.groupby("Category")["Series_1"].mean(), use_container_width=True)
```

### Detailed Explanation

```
+--------------------------------------------------------------------+
| Plotting Engine Comparison                                         |
+-------------------+--------------------+---------------------------+
| Library           | Rendering Engine   | Characteristics           |
+-------------------+--------------------+---------------------------+
| Matplotlib/Seaborn| Server (Raster PNG)| Static, fixed resolution  |
| Plotly            | Client (WebGL/JS)  | Zoom, pan, hover tooltips |
| Native Charts     | Client (Vega-Lite) | Lightweight, fast setup   |
+-------------------+--------------------+---------------------------+
```

1. **Server-Side Raster Rendering (`st.pyplot`):**
   * Matplotlib and Seaborn render plots by generating an image file (PNG) on the server, which is then sent over the network to the browser.
   * *Best Practice:* Always create an explicit figure and axis handle using `fig, ax = plt.subplots()` and pass `fig` to `st.pyplot(fig)`. Relying on global `plt.plot()` calls without an explicit figure handle can cause memory leaks and thread-safety warnings when multiple users access the app simultaneously.
2. **Client-Side Interactive Rendering (`st.plotly_chart`):**
   * Plotly does not send an image. Instead, it serializes the plot definition into a JSON object.
   * The browser receives this JSON data and renders the chart using JavaScript (Plotly.js / WebGL).
   * This enables hardware-accelerated tooltips, zoom boxes, panning, and layer isolation without requiring round-trip communication back to the Python server.
3. **Native Chart Wrappers (`st.line_chart`, `st.bar_chart`):**
   * Built on top of the Altair/Vega-Lite declarative charting library.
   * These are optimized for fast tabular visualizations where writing boilerplate plotting code is unnecessary. They infer columns, axis labels, and legends directly from the DataFrame structure.

## 6. Module 4: Performance Optimization via Caching

### Code

```python
%%writefile app.py
import streamlit as st
import pandas as pd
import numpy as np
import time

st.set_page_config(page_title="Module 4: Caching", layout="centered")
st.title("Module 4: Computation Caching")

@st.cache_data(ttl=60)
def execute_heavy_computation(n_rows: int) -> pd.DataFrame:
    # Simulate an expensive data transformation or database query
    time.sleep(3)
    return pd.DataFrame(
        np.random.randn(n_rows, 2), 
        columns=["Feature_X", "Feature_Y"]
    )

sample_size = st.slider("Select sample size (n):", 100, 2000, 500, step=100)

if st.button("Run Processing"):
    start_time = time.time()
    with st.spinner("Executing pipeline..."):
        result_df = execute_heavy_computation(sample_size)
    elapsed = time.time() - start_time
    
    st.success(f"Completed in {elapsed:.2f} seconds.")
    st.line_chart(result_df)
else:
    st.info("Adjust the slider and click the button to observe caching behavior.")
```

### Detailed Explanation

```
+--------------------------------------------------------------------+
| How @st.cache_data Works                                           |
+--------------------------------------------------------------------+
| 1. Streamlit checks: Function Name + Bytecode + Parameter Values.  |
| 2. Computes an input signature hash key.                           |
| 3. Cache Miss (First run with n=500):                              |
|    - Executes time.sleep(3) pipeline.                              |
|    - Stores the returned DataFrame in an in-memory key-value store.|
| 4. Cache Hit (Subsequent rerun with n=500):                        |
|    - Skips function body execution entirely.                       |
|    - Returns saved DataFrame instantly (<1 millisecond).          |
+--------------------------------------------------------------------+
```

* **The Problem:** Because Streamlit executes top-to-bottom on every interaction, an expensive database query, large CSV load, or machine learning transformation will freeze the user interface on every widget update.
* **The Solution (`@st.cache_data`):**
  * Decorating a function with `@st.cache_data` instructs Streamlit to memoize (cache) the output.
  * When the decorated function is called, Streamlit inspects the function code and input parameters. If that exact combination has been executed before, Streamlit bypasses the function body and returns the stored result from memory.
* **Cache Expiration (`ttl=60`):**
  * `ttl` stands for **Time-To-Live**. The cached result expires automatically after 60 seconds, ensuring that memory is released and fresh data can be queried periodically.
* **Choosing the Right Cache Primitive:**
  * `@st.cache_data`: Use for serializable data structures (DataFrames, dictionaries, arrays, strings). It returns an isolated copy of the data.
  * `@st.cache_resource`: Use for non-serializable, stateful global objects that should not be copied across reruns (such as database connection pools, PyTorch/TensorFlow models, or API client sessions).

## 7. Module 5: Session State Management

### Code

```python
%%writefile app.py
import streamlit as st

st.set_page_config(page_title="Module 5: Session State", layout="centered")
st.title("Module 5: State Management")

# Initialize persistent session keys
if "counter" not in st.session_state:
    st.session_state.counter = 0

if "event_log" not in st.session_state:
    st.session_state.event_log = []

def increment():
    st.session_state.counter += 1
    st.session_state.event_log.append("Incremented")

def decrement():
    st.session_state.counter -= 1
    st.session_state.event_log.append("Decremented")

def reset():
    st.session_state.counter = 0
    st.session_state.event_log.append("Reset")

st.metric("Persistent Counter Value", st.session_state.counter)

col1, col2, col3 = st.columns(3)
with col1:
    st.button("Increment (+1)", on_click=increment, use_container_width=True)
with col2:
    st.button("Decrement (-1)", on_click=decrement, use_container_width=True)
with col3:
    st.button("Reset (0)", on_click=reset, use_container_width=True)

with st.expander("Session State Inspector"):
    st.json({
        "counter": st.session_state.counter,
        "event_log": st.session_state.event_log
    })
```

### Detailed Explanation

* **Why Standard Variables Fail:** If you write `counter = 0` at the top of a script and increment it inside an `if st.button(...)` block, the counter will reset back to `0` on the next interaction because the script restarts from line 1.
* **`st.session_state` Dictionary:**
  * `st.session_state` provides a persistent dictionary attached to each user's unique browser session.
  * Values stored in `st.session_state` survive script reruns.
* **Idempotent Initialization:**
  ```python
  if "counter" not in st.session_state:
      st.session_state.counter = 0
  ```
  This pattern ensures that the counter is initialized only on the user's first visit. On subsequent reruns, the initialization block is skipped, preventing values from being overwritten.
* **Callback Execution Lifecycle:**
  * When a button with an `on_click` parameter is clicked, Streamlit executes the callback function **before** starting the top-to-bottom script rerun.
  1. User clicks the "Increment" button.
  2. `increment()` callback runs $\rightarrow$ `st.session_state.counter` increases from 0 to 1.
  3. Script begins rerun from Line 1.
  4. `st.metric` reads `st.session_state.counter` (now 1) and renders the updated UI.

## 8. Module 6: UI Layout Containers

### Code

```python
%%writefile app.py
import streamlit as st
import numpy as np
import pandas as pd

st.set_page_config(page_title="Module 6: Layouts", layout="wide")

# Sidebar Controls
st.sidebar.header("Global Configuration")
env = st.sidebar.selectbox("Environment", ["Development", "Staging", "Production"])
theme_color = st.sidebar.color_picker("Accent Color", "#1f77b4")
n_records = st.sidebar.slider("Number of records", 10, 100, 25)

st.title("Module 6: UI Layout Containers")
st.caption(f"Active Environment: **{env}**")

# Column Layout
col1, col2 = st.columns([1, 2])

with col1:
    st.subheader("Summary Panel")
    st.markdown(f"Selected Color: `{theme_color}`")
    st.write(f"Sample Size: **{n_records}**")

with col2:
    st.subheader("Data Output")
    synth_data = pd.DataFrame(np.random.randn(n_records, 2), columns=["Val_1", "Val_2"])
    st.line_chart(synth_data)

# Tabbed Layout
tab_data, tab_stats, tab_info = st.tabs(["Raw Data", "Descriptive Statistics", "Metadata"])

with tab_data:
    st.dataframe(synth_data, use_container_width=True)

with tab_stats:
    st.write(synth_data.describe())

with tab_info:
    with st.expander("Container Details"):
        st.write("Expanders and tabs organize visual information and prevent excessive vertical page scrolling.")
```

### Detailed Explanation

* **Context Managers (`with` blocks):** Streamlit uses Python's `with` statement to determine container hierarchy. Any visual component declared inside a `with col1:` block is rendered inside that specific column.
* **`st.sidebar`:** Moves controls and configuration settings into a collapsible left-hand navigation pane, keeping the main page clear for data outputs and charts.
* **`st.columns([1, 2])`:** Divides the page horizontally into responsive columns. The list `[1, 2]` specifies relative width ratios, meaning the second column is twice as wide as the first column.
* **`st.tabs([...])`:** Renders layered tab containers. All tab contents are loaded, but only the active tab is visible. This allows dense information (such as raw data vs. descriptive summaries) to be displayed without taking up excessive vertical screen space.
* **`st.expander(...)`:** Creates a collapsible accordion section that hides secondary or technical details until explicitly opened by the user.

## 9. Module 7: File Ingestion and Media Processing

### Code

```python
%%writefile app.py
import streamlit as st
import pandas as pd
from PIL import Image

st.set_page_config(page_title="Module 7: Files & Media", layout="wide")
st.title("Module 7: File Handling & Media")

uploaded_file = st.file_uploader(
    "Upload a tabular file (CSV) or an image (PNG/JPG)", 
    type=["csv", "png", "jpg", "jpeg"]
)

if uploaded_file is not None:
    if uploaded_file.name.endswith(".csv"):
        df = pd.read_csv(uploaded_file)
        st.subheader("Uploaded CSV Preview")
        st.dataframe(df.head(10), use_container_width=True)
    else:
        image = Image.open(uploaded_file)
        st.subheader("Uploaded Image Preview")
        st.image(image, caption="Uploaded Asset", use_container_width=True)
else:
    st.info("Awaiting file upload.")

st.divider()

st.subheader("Media Stream Players")
c1, c2 = st.columns(2)
with c1:
    st.caption("Audio Player")
    st.audio("https://www.soundhelix.com/examples/mp3/SoundHelix-Song-1.mp3", format="audio/mp3")
with c2:
    st.caption("Video Player")
    st.video("https://sample-videos.com/video321/mp4/720/big_buck_bunny_720p_1mb.mp4")
```

### Detailed Explanation

* **In-Memory File Handling (`st.file_uploader`):**
  * When a user uploads a file, Streamlit loads the raw bytes directly into an in-memory buffer (`io.BytesIO`).
  * You do not need to write temporary files to the disk. The returned `uploaded_file` object can be passed directly to data libraries (e.g., `pd.read_csv(uploaded_file)` or `Image.open(uploaded_file)`).
  * `type=["csv", "png", "jpg", "jpeg"]`: Restricts the file picker to only accept the specified extensions.
* **File Type Verification:** Checking `uploaded_file.name.endswith(".csv")` is preferred over relying entirely on MIME headers, as different operating systems can assign different MIME types to CSV files (e.g., `application/vnd.ms-excel` vs `text/csv`).
* **Media Playback (`st.audio`, `st.video`, `st.image`):** Streamlit handles multimedia decoding natively. These functions accept direct web URLs, local file paths, or raw byte buffers.

## 10. Module 8: Status Notifications and Progress Tracking

### Code

```python
%%writefile app.py
import streamlit as st
import time

st.set_page_config(page_title="Module 8: Status", layout="centered")
st.title("Module 8: Progress & Status Indicators")

if st.button("Start Workflow"):
    with st.status("Executing pipeline workflow...", expanded=True) as status:
        st.write("Step 1: Ingesting data sources...")
        time.sleep(1)
        
        st.write("Step 2: Processing transformations...")
        progress_bar = st.progress(0)
        for i in range(1, 101):
            time.sleep(0.01)
            progress_bar.progress(i)
            
        st.write("Step 3: Validating schema...")
        time.sleep(0.5)
        
        status.update(label="Pipeline completed successfully.", state="complete", expanded=False)
        
    st.success("Execution completed.")
    st.balloons()
else:
    st.info("Click the button to start the multi-step process.")
```

### Detailed Explanation

* **Dynamic Workflow Containers (`st.status`):**
  * Provides an expandable, multi-state progress container designed for multi-step workflows (such as ETL pipelines or ML training loops).
  * States include `running` (displays an active loading spinner), `complete` (displays a green checkmark), and `error` (displays a red alert).
  * `status.update(expanded=False)`: Automatically collapses the status box once processing is finished, keeping the UI clean.
* **Progress Tracking (`st.progress`):**
  * Renders a live progress bar.
  * Accepts an integer between `0` and `100` or a float between `0.0` and `1.0`. Calling `progress_bar.progress(new_value)` updates the bar in real time without refreshing the rest of the page.
* **Visual Alerts:**
  * `st.success`, `st.info`, `st.warning`, `st.error`: Render color-coded notification banners for user feedback.

## 11. Module 9: Batch Execution with Forms

### Code

```python
%%writefile app.py
import streamlit as st

st.set_page_config(page_title="Module 9: Forms", layout="centered")
st.title("Module 9: Batch Processing (Forms)")

st.write("Widgets inside a form do not trigger script reruns until the submit button is clicked.")

with st.form(key="registration_form"):
    st.subheader("User Registration")
    user_id = st.text_input("User ID")
    role = st.selectbox("Role", ["Data Engineer", "Data Scientist", "ML Engineer", "Analyst"])
    access_level = st.slider("Access Level", 1, 5, 2)
    subscribe_alerts = st.checkbox("Subscribe to system alerts", value=True)
    
    # Explicit submit button
    submitted = st.form_submit_button("Submit Record")

if submitted:
    if not user_id.strip():
        st.error("Validation error: User ID cannot be empty.")
    else:
        st.success("Form submitted successfully.")
        st.json({
            "User_ID": user_id,
            "Role": role,
            "Access_Level": access_level,
            "Alerts_Enabled": subscribe_alerts
        })
```

### Detailed Explanation

```
+--------------------------------------------------------------------+
| Without Forms vs. With Forms                                       |
+--------------------------------------------------------------------+
| Standard Widgets:                                                  |
| Change Text -> [RERUN] -> Select Role -> [RERUN] -> Slider -> [RERUN|
| (Causes 3 separate server re-executions)                           |
|                                                                    |
| Form Widgets (st.form):                                            |
| Change Text -> Select Role -> Move Slider -> [Click Submit]        |
| (Causes only 1 single batched execution)                           |
+--------------------------------------------------------------------+
```

* **The Problem:** In complex interfaces with multiple input fields, the default reactive execution model causes an unwanted rerun every time a single character is typed or a single dropdown is changed.
* **The Solution (`st.form`):**
  * An `st.form` acts as an execution barrier.
  * All widgets declared inside the form change their values locally in the browser **without** triggering a server rerun.
  * The script reruns only when the user clicks the dedicated `st.form_submit_button`.
* **Form Rules & Restrictions:**
  * Every form **must** contain an `st.form_submit_button`.
  * Standard `st.button` elements cannot be placed inside an `st.form`.
  * Widgets inside a form cannot have `on_change` or `on_click` callback functions attached to them.

## 12. Capstone Project: Integrated Iris Dashboard

### Code

```python
%%writefile app.py
import streamlit as st
import pandas as pd
import seaborn as sns
import matplotlib.pyplot as plt
import plotly.express as px

st.set_page_config(page_title="Iris Analysis Dashboard", layout="wide")

# Cached dataset loading
@st.cache_data
def load_dataset() -> pd.DataFrame:
    return sns.load_dataset("iris")

df = load_dataset()

# Sidebar controls
st.sidebar.header("Filter Configuration")
all_species = df["species"].unique().tolist()
selected_species = st.sidebar.multiselect(
    "Select Species:", 
    options=all_species, 
    default=all_species
)

# Apply filtering
filtered_df = df[df["species"].isin(selected_species)]

# Main Dashboard Title
st.title("Iris Dataset Exploration Dashboard")
st.markdown("Integrated analytics dashboard demonstrating widgets, caching, session layouts, and multi-engine plotting.")

# KPI Metrics Row
col1, col2, col3, col4 = st.columns(4)
col1.metric("Total Records", len(filtered_df))
col2.metric("Mean Sepal Length", f"{filtered_df['sepal_length'].mean():.2f} cm" if not filtered_df.empty else "N/A")
col3.metric("Mean Petal Length", f"{filtered_df['petal_length'].mean():.2f} cm" if not filtered_df.empty else "N/A")
col4.metric("Species Count", filtered_df["species"].nunique())

st.divider()

# Tabbed layout
tab_charts, tab_data, tab_summary = st.tabs(["Visualizations", "Data Table", "Statistical Summary"])

with tab_charts:
    c1, c2 = st.columns(2)
    
    with c1:
        st.subheader("Feature Correlation (Plotly)")
        if not filtered_df.empty:
            fig_scatter = px.scatter(
                filtered_df, 
                x="sepal_length", 
                y="sepal_width", 
                color="species",
                size="petal_length",
                hover_data=["petal_width"],
                title="Sepal Dimensions vs. Petal Length"
            )
            st.plotly_chart(fig_scatter, use_container_width=True)
        else:
            st.warning("No data matching current filters.")

    with c2:
        st.subheader("Distribution Analysis (Seaborn)")
        if not filtered_df.empty:
            fig_box, ax = plt.subplots(figsize=(6, 4))
            sns.boxplot(data=filtered_df, x="species", y="petal_length", ax=ax, palette="Set2")
            ax.set_ylabel("Petal Length (cm)")
            st.pyplot(fig_box)
        else:
            st.warning("No data matching current filters.")

with tab_data:
    st.subheader("Filtered Dataset View")
    st.dataframe(filtered_df, use_container_width=True)

with tab_summary:
    st.subheader("Descriptive Statistics")
    if not filtered_df.empty:
        st.write(filtered_df.describe())
    else:
        st.info("Select at least one species in the sidebar to view statistics.")
```

### Detailed Explanation

The Capstone Project brings all the individual concepts together into a complete data application:

1. **Performance Layer:**
   * `@st.cache_data` wraps `load_dataset()`. The Iris dataset is loaded into memory only once. Subsequent filter adjustments in the sidebar filter the cached dataset without reloading it.
2. **Global Input Layer:**
   * `st.sidebar.multiselect` provides an interactive filter. Setting `default=all_species` ensures the dashboard is fully populated when first opened.
3. **Data Transformation:**
   * `filtered_df = df[df["species"].isin(selected_species)]` filters the DataFrame in Python. Because of the reactive model, any change to `selected_species` recalculates `filtered_df` and updates all downstream visual components.
4. **Defensive Programming Pattern:**
   * If a user clears all items in the multiselect, `filtered_df` becomes completely empty.
   * Computing `.mean()` or passing an empty DataFrame into Plotly/Seaborn would raise runtime errors.
   * The conditional checks `if not filtered_df.empty:` and ternary expressions (`f"{...:.2f}" if not filtered_df.empty else "N/A"`) gracefully handle empty states by displaying warning banners (`st.warning`) instead of crashing the application.
5. **Multi-Column KPI Row:**
   * `st.columns(4)` creates a clean horizontal summary row for high-level statistics before the user explores detailed views.
6. **Multi-Engine Visualization Tabs:**
   * Tab 1 pairs an interactive Plotly scatter plot with a statistical Seaborn box plot in a side-by-side column view (`c1, c2 = st.columns(2)`).
   * Tab 2 provides access to the raw data via an interactive table (`st.dataframe`).
   * Tab 3 provides aggregate summary statistics (`filtered_df.describe()`).

## 13. Summary Reference Table

| Category | API Primitive | Primary Purpose | Common Beginner Mistake |
| :--- | :--- | :--- | :--- |
| **Inputs** | `st.text_input` | Capture user text strings | Forgetting to press Enter to commit the text value |
| **Inputs** | `st.button` | Execute one-off actions | Expecting a button to remain `True` across multiple reruns |
| **Display** | `st.dataframe` | Interactive tabular data display | Using static `st.table` for large datasets, which slows rendering |
| **Display** | `st.metric` | Display numerical KPIs with deltas | Forgetting to use `delta_color="inverse"` for metrics where lower values are better |
| **Visuals** | `st.pyplot` | Render static Matplotlib plots | Omitting the explicit `fig` handle (`st.pyplot(fig)`), causing thread warnings |
| **Visuals** | `st.plotly_chart`| Render interactive charts | Setting `use_container_width=False`, leading to fixed, non-responsive chart sizes |
| **Caching** | `@st.cache_data` | Persist expensive calculations | Decorating functions that produce un-serializable objects (use `@st.cache_resource` instead) |
| **State** | `st.session_state`| Store variables across reruns | Re-initializing state keys unconditionally on every rerun |
| **Layout** | `st.columns` | Divide horizontal page layout | Adding too many columns on narrow displays, causing element clipping |
| **Batching**| `st.form` | Group inputs to avoid intermediate reruns | Placing a standard `st.button` inside a form instead of `st.form_submit_button` |
